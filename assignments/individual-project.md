
# **Individual Mobile App Project**  
> Build something you’ll actually use after the semester ends.

## **What This Project Is**
This is your chance to create a mobile app that matters to *you*. It can support a hobby, solve a personal problem, help you stay organized, or connect to a device or service you already use. You’ll work independently, but the project is intentionally scoped so you can still keep up with group work and weekly demos.

## **Minimum Requirements**
### **Core Functionality**
Your app must include:
- Three meaningful screens  
- A real data model  
- CRUD operations (Create, Read, Update)  
- Persistent storage 

### **MAUI Skills You Must Demonstrate**
- Shell navigation  
- MVVM with CommunityToolkit  
- Data binding + CollectionView  
- Commands  
- Dependency injection  

### **Choose One Integration**
Pick something that fits your interests:
- Public REST API  
- GPS or sensors  
- Camera or media  
- Notifications  
- BLE or IoT device  

### **UI/UX Expectations**
- Clean, consistent layout  
- One custom control or template  
- Responsive design  
- Basic accessibility

### **Quality Requirements**
- Three unit tests  
- No crashes  
- Clear error handling  
- Organized project structure

## **Documentation**
You’ll submit:
- A short design document  
- Weekly progress updates  
- A final demo video

## **Pacing Guide**
- Week 1: Idea + design  
- Week 2: Models + storage  
- Week 3: Integration  
- Week 4: UI polish  
- Week 5: Testing  
- Week 6: Final demo

## **Goal**
By the end, you’ll have a mobile app you’re proud of and something you can keep improving long after the course ends.

## **Rubric - Individual Capstone Project (100 Points Total)**  

---

## **1. Functional Scope — 20 Points**
| Criteria | Excellent (20) | Good (15) | Adequate (10) | Poor (5) |
|---------|----------------|-----------|----------------|----------|
| Screens & Features | ≥3 polished screens with meaningful interactions | 3 screens with mostly complete functionality | Screens present but limited functionality | Missing screens or major functionality gaps |
| Data Model | Well‑designed model with 3–5+ properties | Functional model with minor issues | Minimal model, weak structure | No meaningful model |
| CRUD | Full Create/Read/Update implemented cleanly | CRUD mostly works with minor bugs | CRUD partially implemented | CRUD missing or unstable |

---

## **2. MAUI Technical Skills — 25 Points**
| Criteria | Excellent (25) | Good (20) | Adequate (15) | Poor (10) |
|---------|----------------|-----------|----------------|----------|
| Shell Navigation | Clean navigation with parameters | Working navigation | Basic navigation only | Navigation broken or missing |
| MVVM + Toolkit | Full MVVM with Toolkit, clean separation | MVVM mostly followed | MVVM inconsistently applied | No MVVM structure |
| Data Binding | Correct binding, CollectionView, observable patterns | Mostly correct binding | Some binding issues | Binding largely incorrect |
| Commands | Commands used appropriately | Commands used but inconsistent | Minimal command usage | No commands |
| Dependency Injection | DI used for at least one service | DI used but not well structured | DI attempted | No DI |

---

## **3. Integration Feature — 20 Points**
| Criteria | Excellent (20) | Good (15) | Adequate (10) | Poor (5) |
|---------|----------------|-----------|----------------|----------|
| Integration | Fully functional integration (API, sensor, media, notifications, BLE/IoT) | Integration works with minor issues | Integration partially implemented | Integration missing or nonfunctional |

---

## **4. UI/UX — 15 Points**
| Criteria | Excellent (15) | Good (12) | Adequate (8) | Poor (4) |
|---------|----------------|-----------|----------------|----------|
| Visual Design | Clean, consistent, polished | Mostly consistent | Basic but functional | Unpolished or inconsistent |
| Custom Control | Custom control/template implemented well | Custom element present but simple | Attempted custom element | None |
| Responsiveness | Layout adapts well to device sizes | Mostly responsive | Some layout issues | Not responsive |
| Accessibility | Labels, contrast, touch targets considered | Mostly accessible | Minimal accessibility | No accessibility effort |

---

## **5. Quality & Testing — 10 Points**
| Criteria | Excellent (10) | Good (8) | Adequate (5) | Poor (2) |
|---------|----------------|-----------|----------------|----------|
| Unit Tests | ≥3 meaningful tests | 3 tests with minor issues | 1–2 tests | No tests |
| Stability | No crashes, good error handling | Minor bugs | Some crashes | Frequent crashes |

---

## **6. Documentation & Demo — 10 Points**
| Criteria | Excellent (10) | Good (8) | Adequate (5) | Poor (2) |
|---------|----------------|-----------|----------------|----------|
| Design Document | Clear, complete, well‑structured | Mostly complete | Basic but present | Missing or incomplete |
| Weekly Logs | Detailed and consistent | Mostly consistent | Minimal entries | Missing |
| Final Demo Video | Clear, polished, shows all features | Shows most features | Shows some features | Low quality or missing |
